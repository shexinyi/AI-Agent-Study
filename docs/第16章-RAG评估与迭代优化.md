## 16.1 没有评估的 RAG 只是 Demo

### 直觉解释

上周你把 BM25 和重排接上了，同事说「好像准了一些」。好像——这不是工程结论。换一份制度、换一个实习生账号、换一句「最多几天」，答案可能立刻回到 5 天或 88 折。

**评估（Evaluation）** 的意思是：先约定「什么叫对」，再用同一套问法反复打分。改切块、换融合、加过滤，分数升了才算迭代；感觉好了只算演示。

Demo 回答一个自己编的问题。上线的 RAG 要回答别人下周才会问出的问题。中间那座桥，就是金标集加指标。

### 生活类比：体检，不是自拍

自拍看气色。体检看血红蛋白。你可以化个妆自拍更精神，验血不会配合你。RAG 的 Hit@1、忠实度就是验血单。简历上写「我们做了 RAG」，面试官下一句一定是：「怎么证明它比关键词搜索好？」没有验血单，这句话说不完。

### 原理剖析：先固定尺子

评估不是上线后的装饰，是开发循环的一部分：

```
改一刀（切块 / 过滤 / 融合） → 跑金标 → 看哪一列掉了 → 再改
```

没有金标，你只能改一刀然后「我觉得行」。有金标，你才知道这一刀救了 ORDER-88，却把「事假最多几天」推进了废止稿。

## 16.2 检索指标与生成指标分别看什么

检索回答：**该看的块来了没有、排第几。**  
生成回答：**开口的句子对不对、有没有超出资料。**

两列必须分开挂。混成一个「好不好」，你会修错地方。

| 指标 | 英文 | 看什么 | 本章怎么算 |
| --- | --- | --- | --- |
| 命中@K | Hit@K | 金标块是否出现在 Top-K | 标题落在前 K 名为 1，否则 0 |
| 倒数排名 | MRR, Mean Reciprocal Rank | 第一块金标排第几 | `1/rank`，没中就是 0 |
| 召回@K | Recall@K | 多块金标找回了几块 | 命中金标数 / 金标总数 |
| 答案正确 | Answer correctness | 必须出现的原文在、禁词不在 | `must_contain` / `must_not_contain` |
| 忠实度 | Faithfulness | 每句都能在命中块里找到 | 多编「通常三天到账」即挂 |

生产里还会看到 **nDCG（Normalized Discounted Cumulative Gain）**（打折后的排序质量）和 **LLM-as-Judge**（用模型打分）。先把手写 Hit@1 / MRR / 忠实度跑绿，再上贵的裁判。

**Hit@3 会骗人。** 金标挤在第 3，Hit@3=1，抽取器却抄 Top-1。ORDER-88 在只向量通道里就是这个样子：第 3 名是真订单，第 1 名是 88 折。

### 图 1：两列分数，两种修法

```mermaid
flowchart TB
    Q[同一问法] --> R[检索]
    R --> G[生成]
    R --> RM[Hit@1 / MRR]
    G --> GM[正确 / 忠实]
    RM -->|低| FixR[改召回、重排、过滤]
    GM -->|低且检索高| FixG[改生成约束、删无出处句]
```

## 16.3 金标集怎么做才不自欺

**金标集（Golden Set / Ground Truth）** 是一组事先写好的「问法 → 应该命中哪一块 → 答案里必须有什么 / 不准有什么」。

自欺的三种写法：

1. **看着排行榜标金标。** Top-1 是什么，gold 就写成什么。分数永远满分，系统从未被检验。
2. **只收自己会问的句子。** 没有单号、没有「最多几天」、没有实习生角色。上线后全是长尾。
3. **用生成结果回填 must_contain。** 模型爱说「一般三到五个工作日」，你就把这句写进金标。那是在给幻觉颁奖。

正经顺序：

1. 先翻原文，圈出命题（「10 个工作日」「ORDER-88 未发货可退」）
2. 再写问法，至少覆盖：同义改写、精确编号、过期陷阱、权限陷阱
3. 金标指向 **标题 / 块 ID**，不是指向「我觉得对的一段话」
4. 锁定文件。改检索代码时不准顺手改 gold；金标要变，单独立项

本章四条（见 `goldenset.json`）：

| id | 问法 | 金标标题 | 必须 / 禁止 |
| --- | --- | --- | --- |
| leave_days | 事假每年累计不超过几个工作日 | 现行事假 | 要「10 个工作日」，不要「5 天」 |
| leave_max | 事假最多几天 | 现行事假 | 同上；专门打过期稿 |
| order88 | ORDER-88 能不能退 | ORDER-88 未发货退款 | 不要「88 折」 |
| tz123 | TZ123 是哪张单 | ORDER-99 已发货售后 | 要 TZ123，不要张冠李戴 ORDER-88 |

`must_not_contain` 不要写成光秃秃的 `5`：现行条款里有「下午 5 点」，会被误杀。写成「5 天」。金标是产品语言，不是正则游戏。

## 16.4 常见病：切块不当、过期文档、权限泄漏

三种病在简历项目 1（企业知识库）里出现的频率，高于「Embedding 模型不够新」。

| 病 | 现场 | 指标怎么响 | 先修什么 |
| --- | --- | --- | --- |
| 切块不当 | 整库糊成一块，5 天和 10 天捆在一起 | 金标标题消失，答案同时含两种数字 | 按标题切；废止稿单独成块并标记 |
| 过期文档 | HR 能看见 2024 草稿，又不过滤 `kind` | 「最多几天」Top-1 变成废止稿 | 检索前丢掉 `deprecated` |
| 权限泄漏 | 实习生关掉 ACL | 废止稿 `acl=hr` 进 Top-K | 角色可见性是过滤器，不是 Prompt |

废止稿写着「实习生不可见」——那是正文，不是门禁。模型读到这句话，不会替你执行 ACL。第 14 章的 `acl` / `version` / `kind` 必须在检索前生效。

### 图 2：评估门禁卡住三种病

```mermaid
flowchart LR
    Idx[语料入库] --> F{kind / acl}
    F -->|未过滤| Sick[废止稿进池]
    F -->|已过滤| Pool[可见块]
    Sick --> Red[CI 红灯：泄漏或含 5 天]
    Pool --> Ret[混合 + 重排]
    Ret --> Gate{Hit@1 且正确且忠实且不泄漏}
    Gate -->|否| Red
    Gate -->|是| Green[允许合并]
```

## 16.5 把评估接入 CI

**持续集成（CI, Continuous Integration）** 在这里只做一件事：有人改了切块、过滤或融合，金标套件必须再跑一遍；有一条 Hit@1 掉了或泄漏了，合并请求不能绿。

本章的门禁不是「宏观平均过 0.8」。宏观会掩盖单号事故。门槛是：

> 每一条：Hit@1 = 1，答案正确，忠实，且 Top-K 不含 forbidden。

`03_diseases_and_ci.py` / `DiseasesAndCi` 失败时进程退出码为 1。GitHub Actions 示意：

```yaml
# 教学示意，不是你们公司的真实流水线
- name: RAG golden set
  working-directory: code/ch16/python
  run: python 03_diseases_and_ci.py
```

Java 同学用同一份 `goldenset.json`：

```powershell
mvn -q exec:java "-Dexec.mainClass=com.agentbook.ch16.DiseasesAndCi"
```

CI 红了先看是哪一列：检索列掉了去改召回；生成列掉了去改「不足则停」和引用约束。不要一红就换 Embedding。

## 踩坑提醒与职场视角

**坑 1：只报 Hit@5。** K 越大越好看。生成器读的是前 1–2 块，先看 Hit@1 和 MRR。

**坑 2：用 BLEU / 和标准答案的字面相似度给 RAG 打分。** 同义改写会被判错；幻觉若碰巧用了标准措辞会被判对。先做包含 / 禁止和忠实度。

**坑 3：金标和代码同一个 PR 里一起改。** 等于自己给自己改试卷。金标变更要单独审。

**坑 4：把「下午 5 点」里的 5 当成毒药。** 禁词要写「5 天」，不要写「5」。

**坑 5：CI 只跑 happy path。** 必须包含编号问、过期问、低权限角色。否则 intern 泄漏不会响。

**坑 6：评估过了就等于业务正确。** ORDER-88 **此刻** 发没发货仍以 `get_order` 为准。金标证明资料没引错，不证明库存。

### 简历上可以写的一句

> 为企业知识库 RAG 建了独立金标集，检索看 Hit@1/MRR，生成看正确率与忠实度；用 CI 挡住切块过粗、过期稿和 ACL 泄漏，禁止看着排行榜回填 gold。

### 本章小结

- Demo 靠感觉，工程靠金标。
- 检索一列、生成一列，修不同的零件。
- Hit@3 会放过排错的 Top-1。
- 切块、过期、权限，比换模型更常是根因。
- CI 红灯是功能，不是羞辱。

## 16.6 常见面试考点

> **高频原题：**「你们的 RAG 怎么评估？指标看哪些？」
>
> **90 秒答法：**
> 我把检索和生成分开评估。检索用金标块算 Hit@1 和 MRR，不迷信 Hit@5。生成看答案是否包含制度原文、是否出现过期数字，以及每一句能否在命中块里找到。金标先写问法和原文命题，再跑系统，禁止看着排行榜标 gold。切块、版本过滤、ACL 进 CI，改召回必须重新跑套件。订单当前状态走工具，不走资料正确率。
>
> **追问 1：**「Hit@K 和 MRR 差在哪？」  
> Hit@K 只问进没进前 K。MRR 问第一块金标有多靠前。K 大时 Hit 人人满分，MRR 还能分出 88 折排第一还是第三。
>
> **追问 2：**「要不要上 LLM-as-Judge？」  
> 金标能自动对的先自动对。裁判模型贵、也不稳定，用来补「措辞是否得体」这类软维度，并抽查它和人工是否一致。
>
> **追问 3：**「评估集怎么防泄漏？」  
> 开发调参用一截，上线验收用另一截。同一问法不要既当训练集提示又当唯一考题。权限类问法按角色拆开。

## 16.7 课后练习（含答案提示）

**练习 1：把 K 从 3 改成 1 再改成 5（必做）**  
重跑示例 1。记下只向量的宏观 Hit。画「K vs Hit@K」。

- 提示：K=5 时只向量也会接近满分，这就是为什么面试不能只报 Hit@5。
- 对照：MRR 几乎不随 K 改口。

**练习 2：故意把 gold 改成 88 折（必做）**  
只改 `goldenset.json` 的 `order88`，再跑 CI。

- 提示：混合管线会红。这就是「看着排行榜标金标」的反面教材——你标错了，好系统反而挂。
- 安全：改完请改回去。金标是合同。

**练习 3：给 CI 加一条「会议室」负例（必做）**  
问「ORDER-99 是哪间房」，gold 仍是售后条款，`must_not_contain` 加「会议室」。

- 提示：不过滤噪音时可能红。重排减分是为这条服务的。
- 产品：负例和正例一样重要。

**练习 4：60 秒口述（必做）**  
画出图 1，并解释为什么「通常三天到账」正确率可能仍过、忠实度必须挂。录音。
